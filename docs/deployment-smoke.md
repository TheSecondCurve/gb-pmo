# 部署后手工冒烟清单（gb-pmo）

> 定位：CI 覆盖不到真实凭证与真实上游（飞书/LLM/对象存储）的集成面（v0.21/v0.37/v0.38 均为线上实测才发现）。
> 每次部署/升级后按本单走一遍，预计 5 分钟。异常项先查 `docker logs`（5xx 恒记 error 级日志，v0.20）。

## 1. 进程与健康

- [ ] `GET /api/v1/health` 返回 `{"ok":true}`
- [ ] 日志含 `[scheduler] enabled` 与 `[bot] …`（enabled 或明确未启动原因）
- [ ] 登录页可打开，管理员账号可登录，全局看板渲染

## 2. 飞书机器人（S20）

- [ ] `node scripts/feishu-ws-test.mjs --db data/gb-pmo.db` 三段全过（token → WSClient 握手 → 收消息）
- [ ] 私聊机器人发「你好」→ 有应答（或 LLM 未配置指引）
- [ ] 私聊发多行带 `- ` 列表的消息（飞书会转富文本）→ 有应答（S20-20 回归点）
- [ ] 群里 @机器人 问一句 → 有应答；群里不 @ 的普通聊天 → 机器人不搭话（S20-16 回归点）
- [ ] 口述「把任务 #N 标为完成」→ 收到确认卡 → 点按 → 回执「已生效」（写路径闭环）

## 3. 定时任务与推送（S6/S7/S18）

- [ ] 配置台「阈值与推送」各 cron 与开关为预期值；改一项保存后日志/行为即时生效（无需重启）
- [ ] 日报到点推送（或配置台手动触发一次「立即对齐」看回显结果）

## 4. 备份（S34）

- [ ] 配置台「运维诊断 → 数据库备份」测试连接通过
- [ ] 「立即备份」成功，历史里出现新记录；对象存储里能看到 `gb-pmo-<时间戳>.db.gz`
- [ ] 每季度做一次恢复演练：下载最新备份 → gunzip → 以 `GB_PMO_DB` 指向该文件起本地进程 → 登录与看板正常（恢复链路脚本化验证见 `server/test/db-migrations.test.mjs`，本项是人工兜底）

## 5. LLM 协议漂移（换模型/端点/提示词后必跑）

- [ ] `node scripts/llm-eval.mjs --db data/gb-pmo.db` 全 PASS 或仅少量 WARN（WARN=散文透出，S20-21 降级会接住但代表漂移；FAIL=协议破损，先别上线）
