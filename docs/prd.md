## 1. 项目组合结构（项目从哪来、长什么样）

> 章节说明：本产品是企业内部项目大脑，**无收入/成本对象**。优先级驱动因素为**项目线并行规模与失控痛感**。

| 项目线 | 并行规模【假设】 | 项目行为单元（一个项目怎么发生） | 典型周期 | 主要消耗 |
|---|---|---|---|---|
| 对外交付线（软件/系统/咨询）【假设为主】 | 待确认 | 客户需求确认 → 口头/合同立项 → 排期 → 交付验收 → 结项 | 1-6 个月 | 交付人力 |
| 内部研发线【假设为辅】 | 待确认 | 老板/产品拍板立项 → 迭代排期 → 发版 → 持续滚动 | 持续 | 研发人力 |

- 立项口径（什么算一个项目）：待确认——同一客户的二期算新项目还是原项目延续？紧急插入的小活算不算项目？
- 优先级拍板人：老板（具体人选待确认）；优先级模型已定为高/中/低三档（D6）。
- 项目类型与任务模板：两个对象（2026-09-30 拍板）——项目类型（软件交付/咨询服务/自由创建…）各自**绑定一个默认任务模板**，多个类型可共用同一模板；立项时选类型即自动套用其模板实例化任务清单。**模板 = 纯任务清单**（每条任务只有标题与顺序，v0.6：无阶段、无预设依赖，任务间不设上下游关系）。预置 + 配置台维护（S17）。

## 2. 项目旅程与价值挖掘

- 项目来源渠道：【假设】老板/负责人在群里或会上口头拍板"立项"，无书面立项记录。
- 项目旅程：立项（模板实例化 + 指定牵头人 + 绑定核心渠道）→ 排期（任务/里程碑，默认责任人=牵头人）→ 执行（IM 讨论自动沉淀 + 状态自动维护 + 任务更新记录不停追加）→ 验收/结项 → 归档复盘。
- 当前卡点：无专职 PM；多项目并行时优先级靠脑记、任务追踪散落在聊天记录里过夜即沉底；关键人被多个项目依赖时无人预警。
- 选定的价值挖掘方向（P0 的注明）：优先级驾驶舱（P0）、关键人依赖预警（P0）、沉默项目预警（P0）、by 项目/by 员工自动梳理与 LLM 建议（P0）；会议纪要抽取（P1）、全局资源日历（P1）、复盘知识沉淀（P2）。

## 3. 现状盘点（数据现在在哪）

| 信息 | 现在记在哪 | 谁记 | 历史数据迁移方式 |
|---|---|---|---|

## 4. 角色与核心场景

### 4.1 角色清单（小团队一人多角，按最简设计）

| 角色 | 人数 | 一句话职责 |
|---|---|---|
| 老板（拍板人） | 1 | 定优先级（高/中/低）、看全局健康度、接收风险预警 |
| 项目牵头人（兼职 PM） | 【假设】3-5 | 立项（必任）、排期、确认抽取与建议、驱动结项；模板任务的默认责任人 |
| 项目成员 | 【假设】10-30 | 领任务（唯一责任人）、群里更新进展、通过本机 Agent 查询/维护/触发 |
| IT/管理员（可兼职） | 0.5 | 维护成员身份表、渠道配置（专题群/通用群）、IM 应用与 LLM 参数、类型与模板、阈值、令牌治理（S17） |

> **系统功能角色（区别于上表业务角色）只有两档：系统管理员 / 成员**（permission-design 小团队裁剪 + D1 全员透明，不做行级权限）。系统管理员在配置台「用户管理」配置成员角色；配置台全部页面与写接口仅系统管理员可访问，普通成员 403（S17-6）；成员的 Agent 令牌（PAT）自助操作走命令行（login.sh），web 不设个人中心页（2026-09-30 拍板）。

### 4.2 核心场景（P0 硬性边界：第一大户项目线 + 项目管理底座，其余项目线 P1 起）

> 场景编号规则：S1、S2… 一经分配**永不复用**；场景废弃时保留编号、标注「已废弃」。测试将按此编号追踪（见 engineering-standards.md）。
>
> **关键设计约束（LLM 信任边界）**：LLM 从聊天记录抽取的一切写入均为「待确认」建议——记录型信息（纯进展描述）可自动生效，建议型变更（任务状态、排期、优先级、责任人）必须经人确认后生效。事件流 append-only、可溯源到原始消息，不可静默篡改。
>
> **P0 项目线假设**：P0 仅覆盖【假设的第一大户项目线 = 对外交付类项目】+ 项目管理底座；若实际失控最严重的是自研线，P0 模板随之替换，其余结构不变。

> **场景 S1（P0）— 牵头人 — 对外交付线**
> - 触发时机：新项目确立（合同签订或口头立项）。
> - 操作内容：选择项目类型（各类型绑定默认任务模板，自动实例化任务清单）或自由创建，填项目名、**牵头人（必填）**、计划周期、优先级（高/中/低）、（可选）客户与关键里程碑；立项向导中**绑定核心渠道**（飞书/企微专题群）。
> - 产生/变更的记录：项目记录（状态=待启动）+ 模板预置默认任务清单（**责任人默认=牵头人**）+ 渠道绑定。
> - 完成标志：项目出现在全局视图，牵头人可在其中排期。
> - 审批/协作：无（老板可事后调整优先级）。
> - 验收标准：
>   - 当立项未指定牵头人时，应阻止完成立项（牵头人是项目必备字段）。
>   - 当用「软件交付」类型完成立项时，应生成项目记录并按其绑定模板生成默认任务清单（无阶段层），任务责任人默认填牵头人（D3）。
>   - 当立项完成时，应引导绑定至少一个核心渠道；未绑定的项目计入管理员待办视图。
>   - 当选择「自由创建」时，应生成不含任何任务的空项目，且支持随时添加任务。

> **场景 S2（P0）— 牵头人 — 对外交付线**
> - 触发时机：立项后进入排期，或执行中调整。
> - 操作内容：为任务指派唯一责任人与计划起止（默认已在立项时填牵头人，此处改派）；登记里程碑；为任务不停追加**更新记录**（谁、何时、写了什么；追加式，只增不改）。
> - 产生/变更的记录：任务/里程碑记录 + 任务更新记录（append-only）。
> - 完成标志：项目排期完整（关键任务均有责任人与日期）。
> - 审批/协作：无。
> - 验收标准：
>   - 当任务责任人被修正后留空、且已设置计划开始日时，应计入「未指派」视图并按日提醒牵头人（兜底监控；默认路径不会出现此态）。
>   - ~~当任务 B 设置任务 A 为前置且 A 未完成时，应将 B 标记为「被阻塞」并在依赖视图可见。~~ **已废弃（v0.6：任务间前置依赖整体裁剪，状态固定三档）**。
>   - 当任务计划结束日早于今日且状态≠完成时，应自动计入逾期任务指标（见第 6 章口径）。
>   - 当为任务追加更新记录时，记录应立即出现在该任务的时间线中且不可修改历史记录；项目结项归档后任务面（含更新记录）转只读。

> **场景 S3（P0）— 系统（大脑·IM 抽取与分拣）— 对外交付线**
> - 触发时机：定时增量（周期由 `scheduler.extractionCron` 配置，默认每小时，S18）+ 管理员按需触发（配置台「立即对齐」或 Agent action 端点）。
> - 操作内容：从两类渠道拉取消息——**专题渠道**（绑定单项目，直接抽取）与**通用群**（系统参数配置的多项目混聊群，先经 LLM 分拣路由到候选项目再抽取）；通过发送者飞书/企微 id 映射成员表归因；生成「记录型」或「建议型」事件。
> - 产生/变更的记录：项目事件（append-only，带原始消息引用与原文快照、发言人归因、置信度）；不直接改动任务状态。
> - 完成标志：事件进入待确认队列（建议型）或直接生效（记录型），并推送对应人。
> - 审批/协作：记录型自动生效；建议型需责任人/牵头人确认。
> - 验收标准：
>   - 当管理员将飞书群 X 配置为项目 A 的专题渠道后，定时抽取应仅从群 X 生成与项目 A 相关的事件。
>   - 当通用群消息到达时，应由 LLM 结合在跑项目上下文分拣出候选项目；分拣置信度低于阈值时应进入「未分拣」池，不误挂项目。
>   - 当消息发送者的飞书/企微 id 无法映射到成员表时，应将事件归因为「未识别发言人」，且不生成针对具体人的任务建议。
>   - 当消息含明确完成信号（如「XX 已上线」）时，应生成任务状态变更**建议**并推给任务责任人。
>   - 当抽取建议的人工采纳率连续一周低于阈值【假设 70%，待拍板】时，应向管理员告警提示调整抽取策略。

> **场景 S4（P0）— 项目成员/老板 — 全线（底座能力，形态 B 落地）**
> - 触发时机：成员/老板随时通过本机 Agent（endpoint skill / MCP）提问、维护、触发。
> - 操作内容：接入走 forge 标准形态 B——一条安装命令装 skill + 终端授权换 PAT；之后对话式完成查询（「我的任务」「B 项目卡在哪」「谁依赖我」）、口述更新（「验收推迟到 10 月 20」「这块交给小王」）、触发功能（立即抽取、生成梳理、手动推日报）。查询与写走 SQL 端点，触发走 action 端点，SKILL.md 中约定两者的使用边界与参数规范。
> - 产生/变更的记录：口述更新生成建议型事件，二次确认后生效；触发类操作产生审计日志。
> - 完成标志：问答返回结构化结果；变更建议落库；触发的任务开始执行。
> - 审批/协作：变更建议需发起人二次确认；触发类操作按 RBAC 白名单校验。
> - 验收标准：
>   - 当成员首次接入时，应能通过一条安装命令完成 skill 安装与授权，凭证仅存本机（skill 包零密钥）。
>   - 当成员询问「我本周的任务」时，应返回其作为责任人的未完成任务列表（所属项目、截止日、阻塞状态）。
>   - 当成员口述「B 项目验收推迟到 10 月 20」并确认时，应对应里程碑/任务的计划日期生效变更，并留事件痕迹。
>   - 当成员口述「这块交给小王」并确认时，应变更任务责任人为小王并通知对方，留事件痕迹。
>   - 当员工通过 Agent 请求触发类功能时，应经 action 端点白名单与权限校验后执行并记审计。
>   - 当 Agent 发起写操作被权限拒绝（403）时，应遵守 skill 守则：不换字段重试、手动补审计字段、只改自己为责任人的对象。

> **场景 S5（P0）— 老板 — 全线（底座能力，dashboard 落地）**
> - 触发时机：老板打开全局视图（interactive dashboard，P0 标配）或通过本机 Agent 询问。

>   - **项目管理**：① 类型与模板（项目类型 CRUD、绑定/换绑默认任务模板、任务模板任务清单编辑——纯任务列表，v0.6；**模板编辑器「AI 起草」生成任务清单草稿，v0.8**）② 渠道（专题渠道绑定项目、通用群清单与分拣阈值、未绑渠道待办、**「立即对齐」手动触发抽取（全部或指定渠道，v0.7）**）③ 阈值与推送（全局阈值、**大脑调度 cron 三件套：信息更新对齐/预警提醒/日报提醒，v0.7**）；

> - 完成标志：配置生效无需重启。

> **场景 S18（P0）— IT/管理员 — 全线（大脑调度与手动对齐，v0.7）**
> - 触发时机：管理员在配置台手动触发；或调度器按 cron 周期自动触发（调度器随进程默认运行，心跳每分钟判定；原 `ENABLE_SCHEDULER` 环境变量总开关已删除）。
> - 操作内容：① **手动对齐**：立即增量拉取全部或指定渠道的新消息，跑完整抽取流水线（收集新记录 → 更新项目最新状态的事件/建议），并回显每渠道结果（拉取条数 / 生效事件 / 待确认建议 / 未分拣 / 错误）；② **调度配置**：三项大脑定时任务（信息更新对齐 `extractionCron`、预警提醒 `alertCron`、日报提醒 `reportCron`）均为标准 5 字段 cron（分 时 日 月 周，支持 `*`、`*/n`、`a-b`、`a,b`、数字），每任务带独立 `enabled` 开关（默认启用），保存即生效无需重启。
> - 产生/变更的记录：手动对齐留审计日志；调度配置变更留配置审计。
> - 完成标志：手动对齐回显结果；cron/开关修改后下一分钟内按新配置触发或停跑。
> - 审批/协作：仅系统管理员（普通成员 403）。
> - 验收标准：
>   - 当系统管理员在渠道页触发「立即对齐」（全部或指定渠道）时，应同步执行增量抽取并回显每渠道结果；拉取失败的渠道应回报错误原因且不影响其他渠道；普通成员调用应 403。
>   - 当修改任一调度 cron 并保存后，调度器应按新周期触发，无需重启进程。
>   - 当保存非法 cron 表达式（字段越界/语法错误）时，应被拒绝并提示具体字段与原因。
>   - 当停用某任务的 `enabled` 开关后，该任务应停止触发；重新启用后按窗口判定恢复（停用期间错过的 cron 时刻，若窗口内已过则补跑一次；日报仍受当日已发去重约束）。
>   - 当进程在日报时点之后启动且当日尚未推送日报时，应在启动后补发当日日报；当日已推送过则不重复。
>   - 调度判定语义：以「上次运行之后到现在」窗口内是否存在 cron 匹配分钟为准；单次运行失败不阻塞其他任务，错误记日志，下个周期重试。

> **场景 S19（P0）— 全局 — 北京时区统一（v0.10）**
> - 背景：团队工作时区为北京时区（Asia/Shanghai，UTC+8，无夏令时）。时间戳一律 epoch 毫秒存储（时区无关，存储层不变）；所有「日历日」的解释（今天/明天/本周/当日零点）必须按北京时区，与部署服务器时区、查询者浏览器时区无关。
> - 实现口径（单一真相源）：JS 侧统一走 `server/db/time.js`（`today()` / `bjDayStartMs()` / `bjWeekStartMs()`）；SQL 侧统一走 db 连接层注册的 `BJ_TODAY()` 函数（与 `today()` 同源）；进程启动固定 `TZ=Asia/Shanghai`（cron 与服务器侧本地格式化兜底）；前端 epoch 时间戳显式按 Asia/Shanghai 格式化。
> - 验收标准：
>   - 当时刻位于北京 00:00–08:00（UTC 前一日 16:00–24:00）时，「今天」的判定应为北京当日而非 UTC 当日（工具函数与 `BJ_TODAY()` 同源，含固定时刻断言）。
>   - 当 Agent SQL 使用裸 `date('now')` / `datetime('now')` 时，应被 400 拒绝并提示改用 `BJ_TODAY()`（显式带时区修饰如 `date('now','+8 hours')` 放行）。
>   - 当 SQL 使用 `BJ_TODAY()` 时应返回北京今日；`BJ_TODAY(<epoch_ms>)` 返回该时刻的北京日历日。
>   - 当日报按「当日已发不重复」判定时，「当日」应指北京日（当日零点=北京零点，与服务器时区无关）。
>   - 当前端展示 epoch 时间戳时，应按 Asia/Shanghai 格式化，不随浏览器时区漂移；纯日期文本（`YYYY-MM-DD`）直接展示，禁止 `new Date('YYYY-MM-DD')` 反解（UTC 午夜语义会在非东八区浏览器错一天）。

> **场景 S20（P0）— 成员 — 全线（机器人指令通道，v0.11）**
> - 触发时机：绑定成员在飞书私聊机器人，或在任意内部群 @机器人（含未登记项目群）；管理员/牵头人在群里 @机器人登记项目。
> - 操作内容：自然语言查询与汇总（LLM 有界循环自主取数、先查后答）；口述登记记录型事件（进展/风险/决策/阻塞，自动生效）；口述任务变更（状态/日期/责任人）产建议型事件并回**确认卡**；群内报名字登记项目群（确认卡后写渠道绑定）；触发类动作（复用 action 白名单：立即抽取/项目梳理/个人梳理/推日报）；`/bind <绑定码>` 绑定飞书账号（仅私聊，10 分钟一次性绑定码由 web 生成）。
> - 产生/变更的记录：项目事件（generator=agent、source_platform=feishu、speaker=发令人、原文快照与消息引用）；渠道绑定（cursor=登记时刻，不回灌历史）；`bot_commands` 审计行（message_id 唯一去重、原文/意图/结果/LLM 次数全留痕）。
> - 完成标志：指令得到基于真实数据的应答；建议/登记经确认卡点按后生效并留痕（decided_by=点按人）。
> - 审批/协作：记录型自动生效；建议型与群登记由确认卡点按人确认（限目标任务责任人/项目牵头人/系统管理员，实时判定）；触发类按 action 白名单语义。
> - 验收标准：
>   - S20-1 当绑定成员私聊提问时，agent 应能多轮自主只读查询（SELECT-only，护栏与 Agent SQL 端点同源）并基于取回数据作答，取不到就明说，不凭记忆编造项目事实。
>   - S20-2 当口述任务变更（如「把任务X标完成/推迟到10-05/转给小王」）时，应生成 pending 建议事件并回确认卡；仅目标任务责任人/项目牵头人/系统管理员点按可生效（走 confirmEvent，decided_by=点按人并留痕）；无权者点按被拒绝。
>   - S20-3 当口述登记纯进展/风险/决策时，记录型事件应自动生效并归因发令人（speaker、原文快照、消息引用）。
>   - S20-4 当未绑定飞书账号私聊时，应只回绑定引导；该用户以有效绑定码 `/bind` 后即绑定为对应成员；过期/已用绑定码明确失败。
>   - S20-5 每条指令应全审计（原文/意图/结果/LLM 次数），message_id 去重（重复投递不二次处理），每成员每日指令限额可配，超限礼貌拒绝。
>   - S20-6 当群@发送者未绑定（含离职成员）时，应静默忽略并留审计，不产生任何事件。
>   - S20-7 当群含外部人员（chat.external）时，机器人一律拒答（安全不变量，非配置开关）。
>   - S20-8 当牵头人或系统管理员在群里 @机器人报名字登记项目且唯一命中时，应回确认卡；确认后写入渠道绑定且 cursor=登记时刻；普通成员发起被拒并提示找牵头人/管理员。
>   - S20-9 当在未登记群 @机器人聊项目时，应可正常问答（无默认项目上下文，写需显式指项目）；配置关闭 `answerUnregisteredGroups` 后未登记群不响应。
>   - S20-10 定时抽取应跳过机器人已处理/已回复的消息（message_id 去重），同一条消息不产生双份事件。
>   - S20-11 `/bind` 仅私聊有效，群里发 `/bind` 应引导去私聊（绑定码是个人凭证，不在群里晒）。

> **场景 S21（P0）— 牵头人 — 项目交付日期与交付周期（v0.12）**
> - 触发时机：立项排期填写交付日期；项目状态切「进行中」时校验；全局列表/详情展示。
> - 操作内容：立项与编辑中「计划结束」语义升格为**交付日期**（复用 `plan_end_date` 字段，不另设新列）；进行中项目的本质 = 启动日（`actual_start_date`，激活自动落）→ 交付日期（`plan_end_date`）的**交付周期**；系统派生展示「剩余 N 天 / 超期 N 天」（交付日在未来为正、已过为负，北京日历日口径，S19）。
> - 产生/变更的记录：项目字段（既有通道）；无新增事件类型。
> - 完成标志：进行中项目必有交付日期，全局列表/详情可见剩余或超期天数。
> - 审批/协作：无。
> - 验收标准：
>   - S21-1 当项目未填交付日期而状态切「进行中」时，应被拒绝并提示先填交付日期。
>   - S21-2 当项目激活成功时，应自动落启动日并派生剩余天数（未来为正、已过为负=超期天数；结项/取消后不再计算）。
>   - S21-3 当进行中/已暂停项目试图清空交付日期时，应被拒绝（交付周期不可缺右端点）。

> **场景 S22（P0）— 系统/管理员 — 飞书项目日历（v0.12）**
> - 触发时机：调度器按 `scheduler.calendarSyncCron`（默认 `*/30 * * * *`，`calendarSyncEnabled` 可停用）对账；管理员在配置台「外部依赖→飞书」初始化日历/立即同步。
> - 操作内容：应用身份在飞书创建**组织级日历**（组织内可搜索订阅，团队成员在飞书日历订阅即见全部项目周期）；把每个项目的起止日期维护为**全日事件**（起=实际启动日‖计划开始日，止=交付日期；结项/取消后止=实际结束日）；同步为**对账式**——按内容 hash 增量 create/patch（未变化零 API 调用），改期/改名/结项下轮自动跟进；**结项/取消项目的事件保留不删除**（标题加【已结项】/【已取消】前缀，日期定格实际周期）。
> - 产生/变更的记录：`calendar_sync` 映射行（project↔event_id↔hash）、settings `calendar.feishuCalendarId`、审计日志。
> - 完成标志：订阅了项目日历的成员在飞书日历看到全部项目的当前周期，与系统内一致。
> - 审批/协作：仅系统管理员可初始化/手动同步（普通成员 403）。
> - 验收标准：
>   - S22-1 当管理员初始化项目日历时，应调用飞书创建组织内可订阅的日历并保存 calendar_id；未配置 appId 时返回明确指引；普通成员 403。
>   - S22-2 当同步运行且有项目内容变化时，应按内容 hash 增量创建/更新事件（未变化的项目不产生 API 调用）；事件为全日、日期闭区间（首日/末日，北京日历日）。
>   - S22-3 当项目结项/取消后同步时，该项目事件应保留并将标题加终态前缀、日期定格为实际周期，不删除。
>   - S22-4 当项目无任何起止日期时，应跳过并在同步结果中计数（不报错）；单项目失败不阻塞其余并在结果回显错误。
>   - S22-5 当配置 `calendarSyncCron`/`calendarSyncEnabled` 时随调度器热生效；未初始化日历（无 calendar_id）时调度静默跳过；管理员「立即同步」回显 created/updated/skipped/errors 并留审计。

### 7.2 本项目特有组件（标准之外的增量）

- **IM 抽取流水线**：飞书开放平台（历史消息 API）+ 企微会话存档（SDK 拉取+RSA 解密）→ 渠道游标管理 → 发言人 id 映射成员表 → 专题渠道直接抽取 / 通用群 LLM 分拣 → 记录型/建议型事件 → 确认生效。申请与配置流程见附录 A。
- **action 端点**（`POST /api/v1/agent/actions`，白名单枚举）：`trigger_extraction`（立即抽取指定项目/渠道）、`generate_project_digest`（触发 S15）、`generate_person_digest`（触发 S16）、`push_report`（手动推日报/梳理）。PAT write scope + RBAC + 审计。SKILL.md 约定：查询/写入用 SQL 端点、触发用 action 端点、每个 action 的参数与错误语义。
- **LLM 适配层**：DeepSeek（OpenAI 兼容）直连薄适配，后台配置 base_url / api_key / model / 超时重试 + 测试连接（D8）；每次调用记录用途（抽取/分拣/日报/梳理/复盘）与关联项目——费用审计 + `suggestion_acceptance` 指标原始数据。换模型=改配置，不引额外网关组件（见 7.3 偏离 #5）。
- **推送通道**：日报/预警/梳理经飞书/企微机器人下发（只发不收，不冒充成员发言；推送语义不变。双向指令通道见 §7.5）。

### 7.5 机器人指令通道（S20，v0.11）

**形态**：同一个飞书自建应用（§附录 A.1）开通机器人能力，事件订阅走**长连接**（纯出站 wss，内网 NAT 后可用，无需公网回调入口）；订阅 `im.message.receive_v1`（私聊 + 群@）与卡片交互回调，网关随单进程内嵌（SDK 懒加载，未安装不阻塞主进程）。配置在 settings `im.feishu` 块：`botEnabled`（默认关）、`botModes { p2p, groupAt }`、`answerUnregisteredGroups`、`commandQuotaPerDay`。

**身份门禁（权限跟人不跟群）**：只认 `members.feishu_id` 映射到的在职成员——私聊未绑定只回绑定引导；群@未绑定（含离职）静默忽略留审计；**外部群（chat.external）一律拒答**（安全不变量，非配置项）。绑定走一次性绑定码：成员 web 登录生成（10 分钟、单次），仅私聊 `/bind <码>`，**凭据不进 LLM 上下文与日志**。管理员也可在用户管理直接维护 feishu id（S17 既有通道）。

**Agent 设计（读自由、写收敛）**：LLM 走有界循环（≤6 轮 LLM / ≤8 次查询/指令），工具两个半——
- `query(sql)`：只读 SQL，护栏与 Agent SQL 端点**同源共享**（单语句、SELECT/WITH/VALUES、DDL/凭据列/sessions 屏蔽、`BJ_TODAY()` 时区护栏、行数截断）；schema 摘要从库内省实时生成，新增表字段零成本可用；
- `metric(id)`：口径捷径，内部走 `queryMetric`（指标口径唯一真相源）；
- `write(kind, payload)`：语义化提议，分发器定性、LLM 不选生效路径——`record_event` 自动生效；`suggest_event` 产 pending + 确认卡；`bind_channel` 限系统管理员/候选项目牵头人 + 确认卡；`trigger` 复用 action 白名单触发类（立即抽取/项目梳理/个人梳理/推日报）。
写载荷必须是真实 ID + 合法枚举值 + 显式日期（今天与星期注入 prompt 做锚），确认卡把解析后的值明示给人核对兜底。回答必须基于取回数据（先查后答），取不到就明说。

**确认卡**：按钮 value 携带 HMAC 签名；点按人实时判定权限（目标任务责任人/项目牵头人/系统管理员）；确认/驳回走既有 `confirmEvent`/`rejectEvent` 唯一生效口子，`decided_by`=点按人。建议同时按既有语义推送目标人（pushes 表）。

**群登记**：@机器人说项目名 → LLM 查询解析唯一命中 → 确认卡 → 点按后 upsert channels（platform=feishu、channelType=dedicated）且 **cursor=登记时刻**（只抽取登记之后的聊天，不回灌历史）；多命中追问一轮，零命中提示用全名。

**审计与去重**：`bot_commands` 表全记录（message_id UNIQUE 去重、platform/chat/sender/原文/意图/结果枚举/LLM 次数/耗时）；机器人发出的回复也落行（kind=bot_reply）；定时抽取按 message_id 跳过机器人已处理/已回复的消息，防同一条消息双入库。

**边界**：机器人以**应用自身身份**应答指令，不冒充成员、不替人回复（§9 禁区不变）；聊天内容出域 DeepSeek 处理（§8 已接受）；不做自由 SQL 写、不做行级权限（D1）。

### 7.6 飞书项目日历（S22，v0.12）

- **形态**：同一飞书自建应用（附录 A.1）补开日历权限（`calendar:calendar`、`calendar:event`），管理员在配置台「外部依赖→飞书」点「初始化项目日历」→ 应用身份创建**组织级日历**（组织内可搜索订阅；团队成员在飞书日历侧搜索名称订阅即见全部项目周期），`calendar_id` 存 settings `calendar.feishuCalendarId`。内网部署下同步为**纯出站推送**（与拉消息同向，不依赖公网入站；ICS 订阅链接方案需飞书云回源内网、不可达，不采用）。
- **对账式同步**：调度任务 `calendarSyncCron`（默认 `*/30 * * * *`，`calendarSyncEnabled` 开关）+ 管理员「立即同步」。每轮全量计算每个项目的期望事件内容，与 `calendar_sync` 映射表按内容 hash 比对：无行→create、hash 变→patch、未变→零 API 调用；单项目失败不阻塞其余，错误回显于同步结果（已建映射的记 `last_error`；create 失败尚无映射行，下轮整体重试）。对账式（而非事件驱动埋点）使改期/改名/结项/历史失败在下一轮自动收敛，无需在每条路由埋钩子。
- **事件口径**：全日事件，日期**闭区间**（飞书全天日程起止=首日/末日，单日两者相同）；起=实际启动日‖计划开始日，止=交付日期；结项/取消后止=实际结束日、标题加【已结项】/【已取消】前缀，**事件保留不删除**（2026-09-30 用户拍板）；无任何起止日期的项目跳过计数；描述带牵头人/优先级/客户。日历日语义走 `server/db/time.js`（S19 北京时区）。

## 附录 A：IM 聊天记录接入调研（申请与配置 step-by-step）

> 调研日期 2026-09-29。两家平台的政策、权限名与价格会变动，落地前以官方文档为准；本附录给出的链接为写作时核对过的入口。

### A.1 飞书：自建应用 + 机器人进群 + 历史消息 API

**结论**：可行且无需额外付费。路径 = 企业自建应用开通消息权限 + 机器人加入项目群 + 服务端定时调用「获取会话历史消息」API 增量拉取。权限由企业管理员审批生效；群内成员可以看到机器人在群。

**Step-by-step：**

1. **创建自建应用**：管理员或开发者登录[飞书开放平台](https://open.feishu.cn) → 开发者后台 → 创建企业自建应用，记录 `App ID` / `App Secret`。
2. **开启机器人能力**：应用详情 → 应用能力 → 添加「机器人」。（不开启机器人能力，消息接口会报错 230006。）
3. **开通权限**：权限管理 → 开通：
   - `im:message.group_msg`（获取群组中所有消息）——**应用身份读取群消息的关键权限，属敏感权限，可能需要提交申请并经平台/管理员审批，周期以开发者后台提示为准，建议最早提交**；
   - `im:message` 或 `im:message:readonly`（获取与发送单聊、群组消息，作为基础权限）；
   - `im:chat:readonly`（获取群信息/群列表）、`contact:user.base:readonly`（用户 userid 与基本信息映射，身份脊柱对齐用）。
4. **发布应用版本**：创建版本并申请发布 → 企业管理员在管理后台审核通过后权限生效。
5. **机器人进群**：将机器人拉入每个项目专题群与配置为通用群的群（群设置 → 群机器人 → 添加；或用「将用户或机器人拉入群聊」API `im/v1/chats/:chat_id/members` 批量操作）。
6. **服务端拉取**：用 `tenant_access_token` 调用 `GET /open-apis/im/v1/messages?container_id=<群 chat_id>`（[获取会话历史消息](https://open.feishu.cn/document/server-docs/im-v1/message/list)），按 `page_token` 分页（page_size ≤ 50），按创建时间升序推进游标。频率限制 1000 次/分钟、50 次/秒，对每小时增量绰绰有余。**前提：机器人必须在该群内**（否则报错 230002）。
7. **机器人指令通道（S20，v0.11）**：同一应用补开——
   - 权限：`im:message:send_as_bot`（以机器人身份发消息）、`im:message.p2p_msg`（收用户发给机器人的私聊消息）、`im:message.group_at_msg`（收群里@机器人的消息）；`im:chat:readonly` 已在基础权限内（读群信息判定外部群）。
   - 事件与回调 → 订阅方式选**「使用长连接接收事件」**（免公网回调，内网 NAT 可用）→ 订阅 `im.message.receive_v1`（接收消息）与 `card.action.trigger`（消息卡片按钮回调，同一条长连接下发）。
   - 依赖：服务端 `npm i @larksuiteoapi/node-sdk`（网关懒加载，未安装时 bot 不启动、主进程不受影响）。
   - 开通顺序：配置台 `im.feishu` 填 `botEnabled: true` 后随进程启动长连接。
8. **项目日历（S22，v0.12）**：同应用在「权限管理」补开日历权限——`calendar:calendar`（读写日历，创建组织级日历）、`calendar:event`（读写日程）→ 配置台「外部依赖→飞书」点「初始化项目日历」（应用身份创建日历并保存 calendar_id）→ 团队成员在飞书日历侧搜索「项目日历（gb-pmo）」订阅。同步为纯出站调用（tenant_access_token），内网可用；全天日程起止日期为闭区间（首日/末日）。

**后台参数（S17）**：`app_id`、`app_secret`、`botEnabled`、`botModes { p2p, groupAt }`、`answerUnregisteredGroups`、`commandQuotaPerDay`（原「拉取周期」由 `scheduler.extractionCron` 承载、verification token/encrypt key 不需要——长连接模式下无回调 URL 可伪造）。

**合规提示**：自建应用读群消息由企业管理员授权即可开通，无强制员工个人同意流程；机器人进群对群成员可见。建议在群公告/员工手册告知「项目群消息会被项目大脑读取归档」——与 D1/D2 透明文化一致。

### A.2 企业微信：会话内容存档（付费，唯一合规读取路径）

**结论**：企微的群机器人只能发不能读；自建应用消息接口只覆盖「用户与应用的会话」。**读取成员群聊/单聊的唯一官方路径是开通「会话内容存档」——付费功能，按被存档员工席位计费，且员工端有知情提示（用户已接受，透明文化）**。

**Step-by-step：**

1. **开通**：管理员登录[企业微信管理后台](https://work.weixin.qq.com) → 管理工具 → 会话内容存档 → 选择版本并缴费开通。可**免费试用 1 个月**先验证链路。价格（2026-01-22 提价后）：办公版 400 元/人/年、服务版 900 元/人/年（不可存档音视频通话）、企业版 1800 元/人/年（可存档音视频通话）——按需存档的员工数计费，建议只给项目相关成员开席位（待确认 #4）。
2. **选择被存档员工**：勾选需要存档的成员（=大脑要"听"到的人）。
3. **员工知情**：被存档员工客户端会收到提示需同意；与外部联系人聊天时对方会看到「聊天内容会被存档」提示，对方不同意则该会话不存档——这是产品机制，无法也**不应**绕过。
4. **生成并上传 RSA 公钥**：`openssl genrsa -out private.pem 2048` 生成密钥对；在管理后台[设置公钥](https://developer.work.weixin.qq.com/document/path/101349)上传公钥（转义换行），私钥妥善保存（将配置在项目大脑后台）。支持多版本公钥（`publickey_ver`）轮换。
5. **记录凭证**：`corpid`、会话存档专用 `secret`、RSA 私钥、公钥版本号；管理后台配置服务器可信 IP。
6. **服务端拉取与解密**（[获取会话内容](https://developer.work.weixin.qq.com/document/path/91774)）：用官方 C 版 SDK（或其封装，如 [WeWorkFinanceSDK](https://github.com/NICEXAI/WeWorkFinanceSDK)，官方 SDK 原生仅 Linux，跨平台可用 Docker）调用 `GetChatData(seq, limit, ...)` 拉取密文 → 对每条消息的 `encrypt_random_key` 做 base64 decode → 用对应版本 RSA 私钥（PKCS1）解密得 `random_key` → 用 `random_key` 解密 `encrypt_chat_msg` 得明文 JSON → 推进 `seq` 游标。
7. **降级预案**：若企微侧暂不开通/试用未转化——企微渠道降级为「成员 Agent 口述更新 + 手动汇报，LLM 归纳」，飞书渠道先行全功能。

**后台参数（S17）**：`corpid`、`msg_audit_secret`、RSA 私钥（PEM）、公钥版本、可信 IP、拉取周期 + 「拉取并解密一条」连通性测试按钮。

**合规提示**：知情同意 + 最小必要（只开必要席位）+ 数据安全管控三原则下合规；建议在员工手册中写明存档用途（项目管理），与 D1/D2 一致。
