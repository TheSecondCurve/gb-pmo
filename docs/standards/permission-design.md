# 标准权限设计

## 默认模型：RBAC（角色-权限-数据范围）

```
用户 ──属于──> 角色 ──拥有──> 功能权限 + 数据范围
```

- **功能权限**：能进哪些页面、能点哪些操作（粒度到"动作"：查看/新建/编辑/删除/审批/导出）。
- **数据范围**：三档 —— 全部数据 / 本部门 / 仅本人。
- 角色由管理员在系统内配置，**不写死在代码里**；代码里只定义权限点清单。

## 小团队裁剪规则

小企业项目常见一人多角（老板=销售=财务）。此类项目不要硬套下表：默认只分「管理员 / 普通成员」两档，数据范围全部放开，审计日志保留。等人员规模或分工明确后再升级。

## 默认角色模板（按项目裁剪）

| 角色 | 功能权限 | 数据范围 |
|---|---|---|
| 系统管理员 | 全部 + 用户/角色管理 | 全部 |
| 业务主管 | 查看/审批/导出 | 本部门 |
| 业务人员 | 新建/编辑本人数据 | 仅本人 |
| 只读 | 查看 | 全部 |

## 登录认证

- 默认：账号密码 + 强密码策略 + 登录失败锁定。
- 可选对接（PRD 约束部分选定）：企业微信扫码 / 钉钉 / AD(LDAP) / 通用 OIDC。
- 对接外部身份源时，本系统内仍维护角色映射，权限不以对方系统为准。

## 实现约束

- 所有服务端动作必须做权限校验，前端隐藏按钮只是体验，不是安全边界。
- 数据范围过滤在查询层统一实现，不允许散落在各业务代码里。
- 关键操作（删除、审批、导出）写审计日志：谁、何时、对什么、做了什么。
