# 标准运行 / 部署方案

## 默认方案：Docker Compose 单机部署（单容器 + SQLite）

```
┌───────────── 一台 Linux 服务器 ─────────────┐
│  Caddy / nginx（反向代理 + 可选 HTTPS）       │
│  app（全栈应用单容器，非 root 运行）          │
│    └─ SQLite 库文件 → named volume（600）    │
│  定时备份：sqlite3 .backup → gzip → 备份目录 │
└──────────────────────────────────────────────┘
```

- **交付物**：`docker-compose.yml` + `.env.example` + 一键部署/升级脚本 + **`skills/` 目录**（Agent skill 包源，必须打进镜像：`COPY skills ./skills`）。
- **HTTPS**：客户有域名用 Caddy 自动证书；纯内网用自签或内网 CA，也可明文（内网可接受，cookie 不 Secure 时应用只 warn 不拒启）。
- **备份**：每日 `sqlite3 "$DB" ".backup ..."` 全量快照（**禁止 cp 热库**）+ gzip + `chmod 600`，本地滚动保留 7~30 天；可选再同步一份到客户指定的另一台机器/对象存储（覆盖式，不留多份）。
- **日志**：应用日志写 stdout，由 Docker 收集；保留 14 天。
- **监控**：默认仅 uptime 探活 + 磁盘告警；不要求 Prometheus 全家桶。
- **环境变量**：必填仅会话密钥（≥32 位随机）；首次启动需 bootstrap 管理员账号。`.env` 不进镜像、不进 git。

## 三种部署模式（PRD 约束部分选定）

| 模式 | 适用 | 运维责任 |
|---|---|---|
| A. 客户自有服务器 | 数据敏感、有内网要求（**最常见**） | 客户出机器，我们出脚本和文档 |
| B. 客户云账号 | 客户已有云资源 | 同上，走客户的安全组/网络策略 |
| C. 托管 | 客户无 IT 能力 | 我们运维，另签运维协议 |

## 升级与回滚

- 升级 = 构建新镜像 + `docker compose up -d`，数据库迁移随启动自动执行。
- 回滚 = 切回上一个镜像 tag + 恢复最近一次 `.backup` 快照（迁移必须向前兼容）。
- **skill 更新不走部署**：客户本机重跑 `install.sh` 即从服务器现取最新版（见 agent-integration.md）。
